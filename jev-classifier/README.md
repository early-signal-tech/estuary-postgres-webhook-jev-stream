# Jev meal classifier: Estuary webhook materialization → FastAPI → Jev

Classifies the grocery carts generated by [`../jev-app`](../jev-app). Estuary captures
`public.cart_updates` from Postgres, and an HTTP Webhook materialization POSTs each new row
to this app. For every row, the app asks Jev (TypeSafe) which meal the cart is being built
for and shows the result on a live web page.

```
jev-app datagen → Postgres cart_updates → Estuary Postgres capture → collection
   → Estuary HTTP Webhook materialization → ngrok → FastAPI (this app) → Jev → web page
```

## What it does

- `POST /webhook/estuary` receives Estuary's request: a JSON array of collection documents.
  It replies 200 right away and queues the documents. Background workers classify them
  (4 Jev calls at a time).
- Each classification is one Jev **Choice** question. The state is `{"cart": ingredients}`,
  and the options are the five meals plus `none`. Jev returns the top meal, its probability,
  and a probability for every option, all of which the page shows.
- `GET /` is the web page. It refreshes every 2 seconds and shows the 12 most recently updated orders, sorted by order id so they don't move around:
  the predicted meal, probability bars for all options, the cart (with the items just
  added highlighted), and how the prediction changed with each update.
- `GET /api/orders` returns the same data as JSON.

Behavior worth knowing:

- **Old rows are skipped.** A new materialization first sends the whole existing
  collection (a backfill). To avoid one paid Jev call per old row, rows with `updated_at`
  older than 10 minutes are skipped. Set `MAX_AGE_MINUTES=0` to classify everything.
- **Resent rows are ignored.** Estuary retries a request on any non-2xx response, so rows
  already seen (by `update_id`) aren't classified twice.
- **Results live in memory.** Restarting the app clears the page.
- Jev never sees the true meal, only the cart contents. The jev-app datagen logs show the
  true meal for each order if you want to compare.

## Setup

### 1. Run the app and the ngrok tunnel

```bash
cp ../.env.example ../.env   # once, in the repo root: TYPESAFE_API_KEY, WEBHOOK_SECRET, NGROK_AUTHTOKEN
docker compose up --build -d
curl -s http://localhost:4041/api/tunnels | jq -r '.tunnels[0].public_url'
```

The last command prints something like `https://abc123.ngrok-free.app`. Open
http://localhost:8000 to see the page. This tunnel's ngrok inspector is on port **4041**,
because jev-app's ngrok already uses 4040.

> **ngrok may only allow one agent at a time.** If the ngrok container fails with
> `ERR_NGROK_108` (too many agent sessions), your plan allows only one online agent, and
> jev-app's ngrok is already running. In that case, stop both ngrok containers and run one
> agent on your Mac that serves both tunnels:
>
> ```yaml
> # ngrok-both.yml
> version: "3"
> tunnels:
>   postgres:   { proto: tcp,  addr: 5433 }
>   classifier: { proto: http, addr: 8000 }
> ```
>
> Run it with
> `ngrok start --all --config "$HOME/Library/Application Support/ngrok/ngrok.yml" --config ngrok-both.yml`
> (the first file holds your authtoken).
> The Postgres address changes when you do this, so update the Estuary capture.

### 2. Create the webhook materialization in Estuary

In the Estuary UI, create a new materialization and choose **HTTP Webhook**:

- **Address:** the ngrok URL, ending with a `/`, e.g. `https://abc123.ngrok-free.app/`
- **Custom headers:** name `x-webhook-secret`, value = your `WEBHOOK_SECRET`
- **Source collection:** the `cart_updates` collection from your Postgres capture
- **Relative path:** `webhook/estuary`

Or use the CLI: fill in `materialize.flow.yaml` and run
`flowctl catalog publish --source materialize.flow.yaml`.

### 3. Watch it

```bash
docker logs -f jev-classifier     # one line per classification
open http://localhost:8000
```

To see Estuary's raw requests, use the ngrok inspector at http://localhost:4041.

## Settings (`classifier` service in `docker-compose.yml`)

| env var | default | |
|---|---|---|
| `TYPESAFE_API_KEY` | (required) | From https://console.typesafe.ai/; set in the root `.env` |
| `WEBHOOK_SECRET` | empty = no check | Must match the `x-webhook-secret` header; set in the root `.env` |
| `MAX_AGE_MINUTES` | `10` | Skip rows older than this; `0` classifies everything |
| `CONCURRENCY` | `4` | Jev requests in flight at once |
| `PAGE_ORDERS` | `12` | Orders shown on the page |
| `CLASSIFIER_PORT` | `8000` | Host port for the app |

## Changing the meals

The meal options are the `criteria` of `MEAL_QUESTION` in `app/main.py`. Each one has a
short description rather than an ingredient list, so Jev uses its own knowledge of the dish
instead of matching items to a list. If you add a meal to `../jev-app/datagen/meals.py`,
add it here too.
